# 工具产品机会评估与落地规划

帮助独立开发者决定是否投入、优先服务谁、首版做什么、如何获取用户和获得收入。可以建议开发、先验证、调整方向或暂缓，不要默认赞成开发。产出决策文档，不自动开发、发布内容、联系用户或收款。

## 需求与市场

复用上下文，优先了解产品任务、形态、阶段、开发者时间预算、技术及已有渠道。只追问会影响判断的少量关键缺口，避免完整问卷。用户要求直接分析时用明确假设继续。

- 用户明确指定市场时优先，覆盖形态默认值。
- 未指定时可以询问；用户未说明则小程序默认国内，App 和网站默认海外。不要因市场未回答反复阻塞。
- 多形态且默认市场冲突时澄清首发形态和市场；若用户要求直接做，分别列情景。
- 海外不等于美国或英语市场。根据需求、语言、付费和获客条件提出首发地区假设，未经验证不当成事实。
- 文档开头注明市场、地区、语言和依据：用户指定、形态默认或分析假设。建议更换形态时不得悄悄改变市场。

## 调查与分析

先阅读 [调查方法](references/research-guide.md)，使用可用联网工具核查竞品、价格、需求信号与渠道。围绕最可能改变决策的未知项调查，避免无休止搜索。

明确区分已核查事实、用户提供的信息、推断和待验证假设。关键判断附来源链接及调查日期。无法联网时输出显著标注的假设版，不能声称已调查、没有竞品或需求已验证。

围绕“具体人群 → 触发场景 → 当前办法及损失 → 功能 → 可观察改善 → 获客入口 → 付费理由”展开：

1. **人群与痛点**：区分使用者与付款者，选择首批细分人群，解释优先级。评估频率、损失、迫切时刻、替代办法与切换成本，避免“所有上班族”等泛化画像。
2. **竞争**：覆盖直接竞品、免费工具、人工、通用 AI 和不解决。分析产品竞争、获客竞争与差异化的可复制性。竞品少不代表需求大，竞争激烈也不直接代表不能做。
3. **产品功能**：给出完成核心任务的最短路径。功能分首版必需、后续附加和暂缓，每项核心功能对应痛点、改善机制和验收信号。评估首版形态、首次价值出现时间、复用理由。允许低频工具采用相应商业模式，避免无依据添加复杂系统。
4. **获客与社媒**：基于目标市场和用户行为选择少数优先渠道，给出内容主题、具体选题或标题、效果演示、行动入口与首次使用路径。区分曝光、目标用户到访、激活和付款。补充合适的搜索、社群或合作渠道，写清执行负担。
5. **变现与可行性**：判断谁付钱、为什么、何时付费、计费单位与免费边界。区分竞品价格和定价假设。考虑开发、接口、数据、托管、支付抽成、客服及维护成本。估算说明币种、计费周期、税费口径、假设与范围，不虚构转化率、收入或终身价值。仅在相关时核查平台、隐私及数据依赖约束。
6. **低成本验证**：优先验证最大风险，设计访谈、原型、落地页或人工交付实验。写明对象与招募渠道、步骤、时间/预算上限、指标和继续/调整/停止标准。标准是建议阈值而非行业事实，小样本结果保留不确定性。

## 可做性与难度结论

每份报告必须分别回答“需求值得做吗”和“以开发者现有资源能做成吗”，最后合并为行动建议。可做性指可交付且可持续经营，不只指能写出代码。按 [调查方法](references/research-guide.md) 中的标准判断，不用无依据的总分或成功概率。

- 需求判断：迫切性、出现频率、现有替代方案是否足够、付费/使用证据，给出支持程度和关键反证。
- 可做性：当前可做 / 满足条件后可做 / 当前不适合做 / 信息不足。明确首版范围、资源假设和必要前提；未知不能算作已满足。
- 难度：分别评估开发实现、数据及外部依赖、获客转化、变现、持续运营，使用低 / 中 / 高 / 未知，逐项解释具体难点与依据。总体难度由关键瓶颈决定，不做简单平均。
- 投入：区分演示原型与可上线首版，给出必要工作项、工作量范围和估算依据；有每周投入时再换算日历周期，并单列外部等待时间。资源或范围不足以估算时说明缺口，不编造工期。
- 降难度方案：说明删减哪些功能、采用何种现成能力或缩小哪个场景可以降低投入，同时检查核心用户价值是否仍成立。列出继续开发前必须验证的阻塞项和停止条件。

## 文档与验收

按 [报告结构](references/report-template.md) 生成完整中文 Markdown 文件，默认保存为当前工作区 `reports/产品简称-YYYY-MM-DD.md`，同名时保留旧版。用户指定路径或格式优先；无写入能力时给完整可保存文本并说明限制。

开头先给需求价值、可做性、总体难度及关键瓶颈、行动建议、依据、最大未知项和最便宜的下一步。篇幅随复杂度调整，避免填充模板。最终给可点击的文件链接与简短结论。

交付前检查：市场是否贯穿竞品、渠道、货币与功能；关键判断是否有证据或明确假设；是否找过反证；首版能否完成核心任务；功能、营销承诺和付费理由是否一致；是否将点赞和抱怨误作购买意愿；是否说明什么新证据会改变结论；文件是否真实保存且引用支持相应说法。
